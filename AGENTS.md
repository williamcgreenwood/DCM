# Pillars DCM — permanent project instructions

## Mission and authority
Build the ChatGPT-native Dynamic Cushion Model (DCM) from supplied HARs and canonical project sources. Preserve universal sport/event/entity/market contracts while delivering CFB first. Lifecycle: HAR → complete-board accounting → ChatGPT research → forecasts/props/portfolio → freeze → settlement → audit → future-only learning. `main` is the only supported runtime.

The owner grants standing authorization for normal coding, review, commits, pushes, PR creation, checks, and merges. Continue without repeated reconfirmation. Use short-lived branches and normal protected GitHub gates. Platform safety/authentication still applies: never bypass reviews, weaken tests, force-push, delete history, publish secrets/raw HAR/private data, or claim scientific/predictive certification without evidence. If blocked, state the exact cause and saved SHA.

## One-path Git workflow (strict)
Exactly one active implementation branch and one active implementation PR exist at a time. Start each increment from latest `main`; finish producer → consumer → tests → evidence → commit → push → CI → merge → verify `main`. Close/archive superseded PRs and stale task branches. Never bulk-merge old branches or develop against an obsolete base. Audit/design-only requests do not mutate the repository.

## Start/finish contract
At start read `AGENTS.md`, bootstrap/Constitution, engineering standard, live status, requirement trace, and latest verified checkpoint. Verify live SHA, dirty state, tools, inputs, and permissions; do not trust stale reports. Find existing functionality before adding code. Review every touched module and prefer repair/reuse over duplicate engines. At finish report separately: implemented, tested (including failures/skips), pushed, merged, operational, performance, recovery, predictive, and universal states, with SHA/CI evidence.

## Inputs, privacy, and research (invariant)
The owner supplies HAR files only. The owner supplies no research facts, game logs, injuries, lineups, news, statistics, sources, or model inputs. On every run—always, including rain/sleet/snow and leap years—ChatGPT must explicitly perform fresh, claim-specific external research using available host tools after HAR extraction. Reuse is allowed only for valid, hashed, cutoff-safe evidence; revalidate freshness and record what was reused. Never invent or silently fill missing evidence. Raw HARs, cookies, tokens, credentials, response bodies, and private runtime output stay quarantined and are never echoed or committed.

Account every offered side before exclusions; never truncate to Top100. Resolve actual sides, aliases, competition/event, modifiers, and exact `MarketDefinition`. Unsupported or unknown definitions fail closed. Preserve observed/available/valid times, cutoff, authority, independence, contradiction, freshness, source/content/claim hashes, and failure state.

## Engineering and algorithmic constitution
One installed `src/dcm` package is canonical; retain `src/dcm/research`. No runtime imports from experiments, donor quarantine, or artifacts. Use typed, versioned schemas; explicit units/IDs/times; pure computation separated from I/O; injected clocks/RNGs; bounded resources; parameterized queries; canonical hashes; explicit errors; safe migrations. SQLite is a transactional local index; Drive is durable storage, not a database. Upload verified snapshots, not live SQLite files. Route writes through the canonical folder-ID registry.

Every change inherits `DCM-ALGORITHM-CONSTITUTION-v1.0.0-20260903`, `docs/architecture/DCM_ALGORITHMIC_CONSTITUTION.md`, the permanent `docs/engineering/ALGORITHM_CONSUMPTION_LAW.md`, and `docs/engineering/DCM_CODING_AND_PROMPT_STANDARD.md`. Preserve stable REQUIRED_CORE/REQUIRED_CONDITIONAL/CHALLENGER entries. Registered algorithms must be executed only when applicable and must declare applicability, inputs, producer, consumer, fallback, complexity, tests, benchmarks, and lineage. Use Exact-first indexes (BoardStore/BoardIndexes) and hash/composite lookup first; then structured temporal/lexical indexes; deterministic grouping; filter/group/index/partial-select/final-sort. Approximate retrieval cannot establish truth. No capability disappears without a tested ADR.

## Runtime/model rules
Build dependency-first versioned graphs: BoardGraph, MarketDemandGraph, RequirementGraph, AcquisitionActionGraph. Compute shared state once at the highest reusable scope; invalidate only descendants. Freeze ends backward mutation. Separate opportunity, efficiency, forecast probability, reliability, uncertainty, and selection utility. Shared EventWorlds conserve primitives; composites derive from them. No leakage, random CV across correlated events, or test-fold training. Keep LR/champion/challenger/calibration/OOD/ESS real and consumed; promotion requires predeclared chronological evidence. Never force a card or confidence-to-probability mapping. Show genuine playables first, then ranked/full-board accounting; unknown settlement rules block recommendations.

## Public-safe operational metadata
Documentation and committed manifests must not expose absolute host paths, workspace/mount locations, internal checkpoint paths, or environment-specific filenames. Replace them with portable relative paths or `<RUN_ROOT>` / `<WORKSPACE>`. Preserve safe hashes, counts, schema versions, status states, lineage, and implementation behavior. After sanitization regenerate affected artifacts, run tests and inventory checks, wait for CI, then merge normally.

## Acceptance and recovery
Test positive paths and correct abstention, including missing side, source failure, stale/conflict, unsupported league, resume, and privacy gates. Separate software, CFB/NFL operation, performance, recovery, predictive, and universal states. Checkpoint before exhaustion; resume must equal uninterrupted output. Drive writes are validate → stage → hash → enqueue → upload → verify → publish; if Drive is absent continue local-only with an explicit durability blocker. No unsupported “10/10”, profit, completion, LR promotion, or host-certification claim. Main is supported code, not scientific certification or permission to issue bets.
