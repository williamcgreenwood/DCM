# PILLARS DCM — permanent project instructions

## Mission, scope, and autonomy
Build one ChatGPT-native universal DCM: CFB first, NFL second, then other sports. Preserve Sport → Competition → Event → Affiliation/Subject/Counterparty/Environment → MarketDefinition → Offer. Runtime: HAR → full accounting → research/reuse → evidence → features/models → forecast → portfolio → freeze → settlement → future-only learning. No required VM, daemon, GPU, compiler, hidden checkout, or undocumented host capability. `main` is the only supported runtime.

The owner supplies **HAR files only**. Do not ask the owner for player research, injuries, lineups, schedules, game logs, source URLs, statistics, or model inputs. Extract identities, schedules, observed platform fields, and capture times from each HAR; then use available host research tools to obtain permitted public sport facts. Platform-offer availability, line, side, modifier, period, and status may come only from an observed platform capture or approved offer source—never from research or inference. If research tools, an authoritative source, or a current offer cannot be obtained, record an explicit acquisition failure/stale state and abstain; never shift that work back to the owner.

The owner authorizes normal autonomous work: inspect, code, test, commit, push, create/update PRs, run checks, request review, and merge once normal gates pass. Never bypass authentication, branch protection, reviews, checks, privacy controls, or platform safety; never force-push, weaken tests, delete history, publish secrets/raw HAR/private data, or call a research ranking a prediction without its gate. When blocked, state the exact control, failed action, saved SHA, and next unblock action.

## One-path execution and Git control
Start by reading this file, bootstrap/status, Constitution, engineering standard, requirement trace, verified checkpoint, and current GitHub state. Verify SHA, dirty state, branch, tools, permissions, and inputs; historical reports are clues only. Find existing producers/consumers before adding code. Work baseline/reconcile → policy/routing → canonical package → CFB → NFL → recovery → measured acceleration → other sports. Each tranche closes producer → consumer → tests → evidence → commit → push → CI/review → merge → `main` readback. Report implemented, tested, pushed, merged, operational, predictive, recovery, and blockers separately.

Enforce exactly one active implementation branch and PR. Start it from latest verified `main`; merge only after required checks and normal review; close/archive superseded work; never bulk-merge old branches or create parallel engines.

## Engineering and algorithms
Keep one installed Python package under `src/dcm`; no runtime imports from experiments, donor archives, or artifacts. Python owns orchestration, research, domain, models, and APIs; SQLite owns transactional indexes/outbox. DuckDB/Polars/native/Rust are optional only after measured end-to-end benefit, semantic/RNG parity, portable fallback, packaging, and rollback tests. TypeScript is UI/client only.

Require typed versioned schemas, canonical IDs/units/UTC times, pure computation separated from I/O, injected clocks/RNGs, bounded resources, parameterized queries, canonical hashes, explicit errors, and safe migrations. Every active algorithm must declare applicability, inputs, producer, consumer, fallback, complexity, tests, benchmarks, telemetry, and lineage. Registration is not execution. Prefer exact/hash/composite indexes, then structured temporal/lexical retrieval, deterministic grouping, filter/group/index/partial-select/final-sort. Approximate retrieval never establishes truth. Preserve REQUIRED_CORE, REQUIRED_CONDITIONAL, and CHALLENGER entries; no capability disappears without a tested ADR. Use BoardGraph, MarketDemandGraph, RequirementGraph, and AcquisitionActionGraph with bounded pre-freeze feedback and true descendant invalidation; freeze ends backward mutation.

## HAR, research, truth, and learning
Raw HARs, cookies, tokens, credentials, response bodies, and private run databases are local quarantine only: never print, fixture, commit, upload to GitHub/Drive, or send to a model. Account every offer before exclusions; do not truncate to Top100. Resolve actual platform line, side, modifier, period, status, aliases, event, and MarketDefinition; missing/contradictory offered-side data fails closed.

External research supplies permitted sport facts, never platform offers. Reuse only valid content-addressed evidence/scopes and acquire only gaps. Every claim needs authority/source, scope/field, typed value/unit, publication/availability/retrieval/validity times, content/claim hashes, parser version, cutoff verdict, independence/lineage, and explicit absent/conflict/stale/failed states. Reject post-cutoff evidence and outcome leakage. Fixtures are engineering evidence, never predictive proof.

Separate opportunity, efficiency, probability, reliability, data quality, volatility, fragility, OOD risk, rank stability, regret, and selection utility. Shared conserved EventWorld primitive ledgers feed composites. Use hierarchical/shrinkage/state/distribution models and chronological leakage-free ML; maintain real champion/challenger, calibration, drift, ESS, uncertainty, and research-bandit telemetry. A line buffer tests adverse movement (Higher at L+Δ; Lower at L−Δ) derived from observed movement and forecast uncertainty; it cannot validate a stale/unavailable offer. Unknown rules, insufficient evidence, trivial lines, or correlated portfolios block affected selections. Show complete-board accounting, a Top100 **research** queue, a Top25 only after evidence/model gates, and 0–6 genuine playables or abstention—never force a card.

## Storage, public safety, and acceptance
Drive is durable object storage, not a database. Route facts, indexes, models, runs, settlements, logs, and checkpoints through the verified root/folder registry. Validate → stage → hash → enqueue → upload → verify → publish reference; upload snapshots, never live SQLite. Keep local indexes/outbox, append audit history, reconcile interruptions/conflicts, and restore from the latest verified checkpoint. If Drive is unavailable, continue local-only with an explicit durability blocker. Never delete unknown or duplicate-looking data without authority.

Before public push, replace workstation/container/mount/private-run absolute paths with portable paths or `<RUN_ROOT>`/`<WORKSPACE>`. Preserve safe hashes, counts, schema versions, run states, and implementation behavior; regenerate artifacts, rerun tests/inventory, wait for CI, then merge normally.

Test positive paths and correct abstention: unit, contract, property, temporal, restart, conflict, security/privacy, package/install, integration, inventory, CI, and representative benchmarks. Include full-board/HAR accounting, source/research coverage, lineage, freeze/settlement separation, and failure diagnostics. Keep `LR000000`, predictive claim `NONE`, production-root false, and host-performance false until independently earned. Every pass adds an immutable engineering record with commands/results/measurements and exact next action. Main—not chat, stale branches, or archives—is supported truth.
