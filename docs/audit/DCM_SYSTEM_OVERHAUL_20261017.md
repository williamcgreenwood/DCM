# DCM system overhaul audit and execution contract

Baseline: `d795084f8d2b87b002b7bc41209e2474f5165da1`. This document distinguishes inspected code, saved run receipts, local generated benchmarks, and work still requiring the supplied captured bytes. The static inventory in `FAILURE_BOUNDARY_INVENTORY.json` covers every `src/dcm` Python module. Its call-site counts identify review candidates, not proven bugs or proof of safety.

## Evidence and current status

The supplied folder contains the October 16/17 capture set and prior sanitized run receipts. The saved receipts report 32 named files and 11 unique byte contents. Different labels on identical bytes cannot establish independent prop, schedule, injury, league, or ranking coverage. The attempted combined run exited `-9` after 1,285.6 seconds; SIGKILL is established, while the exact kernel/host cause remains unverified here. The completed sport cohorts and partial Soccer composite are described in `RUN_FAILURE_AND_RECOVERY_20261017.md`. The previous private run state was unavailable; this audit downloaded and independently hashed one representative of each of the 11 unique contents. It has not rehashed all 32 named copies.

The October 15 subset also includes a 180 MB screenshots PDF. Its page extraction, hashes, and offer reconciliation remain separate unclosed input gates. No modeling, research, settlement, calibration, or production selection is certified by this code audit.

## Static boundary scan

The generated inventory found 272 Python modules, 1,931 function definitions, 326 exception-handler sites (32 catching `Exception`, `BaseException`, or bare), and 703 calls matching the scan's I/O/process operation names. Of those calls, 528 have no `try` directly around them. These numbers are **not** 528 confirmed missing catches: a caller, transaction context, or process supervisor can own the failure boundary, and method names such as `run` can be unrelated to external I/O. Review each flagged site by its actual call graph, transaction, and receipt. An indiscriminate `except Exception: pass` would make the system less trustworthy.

The project standard requires Python as the canonical orchestration and probability engine. Language migrations to SQL/DuckDB/Polars or Rust need a representative bottleneck, fallback, semantic parity, and operational evidence. A blanket rewrite into another language would enlarge the unverified surface and cannot solve missing observations or a killed process by itself.

### Changes in this branch

The slate parent supervisor writes an atomic progress/failure receipt, limits wall time, stall time, RSS, and cgroup use, and refuses a zero-exit child without valid terminal hashes. Source capture aliases are byte deduplicated while every named file remains in the manifest. In-process all-source fallback after composite failure was removed.

The runner now uses compact incremental reconciliation on multi-HAR inputs. The final canonical reconciliation still replays all attempts and asserts equality with the incremental board; scope attempts and row history remain intact for cutoff replay. The composite timeline records additions, removals, and changes instead of every unchanged projection in every capture. `board.json` is streamed to an atomic temporary file instead of building a second full JSON string in memory. A malformed acquisition-action accounting file now fails with `ACQUISITION_ACTION_ACCOUNTING_INVALID` instead of silently recording zero outstanding actions.

The actual 11-content composite produced 157,789 final offer rows, 5,621 typed Insights claims, and 27 scope attempts in 27.12 seconds at 1,611.7 MiB peak RSS under a 4 GiB process limit. The large Soccer capture alone was 207,322,922 bytes and parsed to 129,554 rows in 10.71 seconds at 1,443.2 MiB peak RSS. These measurements exclude download time and the rest of the runner.

The first full account-only runner replay reached terminal offer accounting, then raised `MemoryError` in `build_requirement_graph` while expanding dependency edges: 6,695 research requests and 157,789 offers, 212.31 seconds, 4,664.6 MiB peak RSS under a 5 GiB address-space limit. The graph builder scans parent scopes per child and holds BoardGraph, MarketDemandGraph, indexes, nodes, reverse indexes, and edges concurrently. This is a concrete independent failure in addition to the earlier SIGKILL. A rerun with a 50,000-offer account-only graph budget completed accounting for all 157,789 rows in 158.86 seconds at 3,239.9 MiB peak RSS. It emitted a hash-verified `RESEARCH_GRAPH_REQUIRES_PARTITION` deferral and a readable checkpoint with `RESEARCH_GRAPH` pending; no research graph, numeric forecast, or production selection is claimed. The premodel classification includes 3,822 rows labeled `MODELED` by the older classifier; the account-only output now marks this as premodel eligibility and `forecastExecuted: false` to prevent treating that state as a probability result.

### Real-capture recovery replay

After indexing exact dependent offer/claim IDs instead of attaching unbound parent requests to every offer, and changing the graph artifact writer to atomic streaming JSON, the same 11 unique captured HAR contents completed the account-only research path. The replay accounted for 157,789 offer rows and 6,695 research requests, wrote the evidence graph, entity graph, staged research and feature-store outputs, and returned `COMPLETE_WITH_UNSUPPORTED_ROWS`. It completed in about 8 minutes under a 5 GiB virtual-address limit; the highest external RSS sample was about 4.1 GiB. The previous run failed before completing any October 17 cohort, so this replay is evidence for the combined captured input bundle only; it does not prove date-separated October 16 and October 17 forecasts.

The retry crossed the earlier graph failure boundaries and finished, but it is still a resource-heavy account-only path. During that successful run, the feature-store stage held CPU for more than two minutes without writing a new artifact. This points to a further CPU optimization opportunity: `persist_feature_store` materializes feature records for all research packets before writing JSONL, recalculates rolling windows per packet, and then hashes a second full feature list. This has not yet been rewritten to a streaming producer/consumer contract or benchmarked independently. The freeze semantics are being corrected to emit `executionMode=ACCOUNT_ONLY_NO_FORECAST`; previous account-only freezes incorrectly said `RESEARCHED_MODELED` despite `forecastExecuted=false`.

Generated 48,000-row/four-capture complementary-scope benchmark: full timeline 120,000 transitions, 6.80 seconds, 108.2 MiB traced peak; compact timeline 48,000 transitions, 3.20 seconds, 96.5 MiB traced peak. Both final reconciliation hashes matched. This workload is synthetic and does **not** establish a peak RSS or timing claim for the user's 32 files. The large-run output contract now carries `timelineMode=BOARD_CHANGES_ONLY`; consumers requiring a repeated per-capture retained-state event must request the legacy full mode. The saved per-scope attempts still support as-of replay.

2. Replace whole-file HAR JSON loads and duplicated parsed structures on large captures with a bounded parser/spill design, and verify parity for schedule, offer, and Insights claim semantics. Test malformed and compressed bodies, aliases, truncation, disk full, and resume.
3. The pathological parent-scope cross scan is replaced with exact indexed joins and the completed 157,789-row replay verifies graph artifact generation on the supplied unique captures. Continue with sparse/batched graph storage and lower the measured peak RSS. Convert the 2,700-line `runner.py` sequence into named stage transactions with explicit input/output hashes, idempotency keys, timeout/resource budgets, checkpoint commits, and typed error propagation. Keep one canonical producer/consumer graph and prevent partial promotion.
4. Apply the inventory to each active research, sport, model, ranking, freeze, settlement, cache, and archive boundary. For each catch, define whether it retries, abstains, rolls back, or fails the run. Add fault injection at the boundary; pure functions generally propagate typed errors instead of swallowing them.
5. Close the observed CFB research batch cap mismatch, import actual cutoff-safe observations with host tools, and implement unsupported sport/market backends only with explicit outcome definitions and evidence. Run all seven applicable gate evaluators without equating a readiness receipt to execution or certification. The completed replay is account-only; forecast, ranking, settlement, and production certification remain unverified.
6. Verify remote artifact readback hashes and an external watcher for total container loss. A child/parent process guard cannot write a failure receipt if the entire host disappears.
7. Push through the one protected branch/PR, run full CI, review actual performance and recovery evidence, merge only when the increment's claims pass, and verify `main`. Full-system certification and predictive claims remain open until the separate operational evidence exists.

Acceptance for the complete overhaul requires every observed offer to have an exact terminal state, no date leakage, byte alias accounting, reproducible cutoff replay, every stage either complete or typed blocked, fault-injected recovery, bounded memory and time on the actual capture set, and the same final hashes after resume as an uninterrupted run. `LR000000`, predictive claim `NONE`, and zero certified playables are the honest current states.
